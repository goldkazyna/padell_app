# План: админка клуба в мобильном приложении

**Дата старта:** 2026-04-28
**Цель:** дать `club_admin` возможность создавать и управлять турнирами с телефона. Все типы кроме «Классического».

---

## Архитектурные принципы

1. **Бизнес-логика — единая.** Все сервисы (`AmericanoService`, `MexicanoService`, `TeamTournamentService`, `KingOfCourtService`) уже существуют. Веб и мобила — два UI поверх одних и тех же сервисов.
2. **Новые мобильные эндпоинты — тонкие wrappers** над существующими сервисами. Не дублируем логику.
3. **Поэтапно.** Каждый этап = отдельный коммит/релиз. После каждого — проверка вживую.
4. **Не ломаем.** Веб-админка работает как раньше, ни одна правка её не задевает. Мобила добавляет, не заменяет.
5. **Только `club_admin`.** Модераторов и `super_admin` НЕ покрываем сейчас.
6. **Только 4 типа:** `americano`, `mexicano`, `team`, `king_of_court`. Классический исключён.

---

## Этапы

### ЭТАП 1 — Фундамент: роль и доступ

**Цель:** залогиненный `club_admin` видит **на главной странице** новый блок «Управление клубом» с большими кнопками. Обычный пользователь блок не видит.

#### Бэкенд

- В `/api/mobile/profile` и `/api/mobile/auth/...` добавить в user-DTO:
  - `role` (string)
  - `is_club_admin` (bool) — `true` если у user есть запись в `club_admins`
  - `admin_clubs` — массив `[{id, name}]` клубов где user админ (через `User::adminClubs()`)
- Если `is_club_admin = false` — `admin_clubs` пустой массив

#### Мобила

- `User` модель (Dart): добавить поля `role`, `isClubAdmin`, `adminClubs: List<AdminClubRef>`
- `ProfileService` / `AuthService` — парсинг новых полей
- На `HomeScreen` (главная), если `user.isClubAdmin == true`:
  - Под существующим блоком «Создать турнир» (или вместо — обсудим), показываем секцию **«Управление клубом ADD Padel Almaty»** с CTA-кнопками. На этапе 1 — заглушки:
    - «Мои турниры» — открывает `AdminTournamentsScreen` с заглушкой
    - «Создать турнир» — открывает заглушку
  - Если `admin_clubs.length > 1` — выбор клуба сверху (пока считаем что admin одного клуба, но коду оставляем гибкость)
- Стиль кнопок — единый, можно похоже на «Создать турнир» CTA (градиент, иконка, заголовок, подзаголовок)

#### Что проверить после этапа

- ✅ Обычный пользователь: главная как раньше, блока «Управление» нет
- ✅ Админ клуба: на главной появился блок с названием клуба и кнопками
- ✅ Тап по кнопке → открывается экран-заглушка «Скоро»
- ✅ Веб-админка работает как раньше
- ✅ Logout / login заново — блок появляется/исчезает корректно

---

### ЭТАП 2 — Список турниров клуба

**Цель:** админ видит все турниры своего клуба со всеми статусами, может тапнуть и провалиться в детали.

#### Бэкенд

- `GET /api/mobile/admin/club/{clubId}/tournaments`
  - Проверка: user является админом этого клуба (`club_admins`)
  - Возвращает все турниры клуба со всеми статусами
  - Сортировка: `start_date DESC`
  - Поля: `id, name, type, type_name, start_date, status, status_name, max_participants, participants_count, pending_count` (для модерации)

#### Мобила

- `AdminScreen` → список клубов (если их больше 1) → `AdminClubScreen`
- `AdminClubScreen` с табами по статусам: `Черновики`, `Открытые`, `Идут`, `Завершены`
- Карточка турнира: тип, дата, название, бейджи статуса + плашка «N заявок на модерации» если есть pending
- Тап → пока заглушка «Этап 3 в разработке»

#### Что проверить

- ✅ Список турниров клуба корректный
- ✅ Цифры участников совпадают с веб-админкой
- ✅ Pending-плашка появляется когда есть заявки на модерации
- ✅ Веб-админка не сломана

### ЭТАП 3 — Управление существующим турниром

**Цель:** админ может из мобилы провернуть весь жизненный цикл турнира кроме создания.

#### Что входит

- Модерация заявок (approve/reject)
- Редактирование (название, даты, уровни, max_participants)
- Удаление участника
- Запуск турнира (`start`)
- Ввод счёта матчей (для всех типов — раунды, плей-офф)
- Генерация следующего раунда (Mexicano, KOC)
- Генерация плей-офф (Americano, Mexicano, Team)
- Замена участника на другого (если резерв)
- Завершение турнира (`finish`) — применение ELO

#### Бэкенд

Все методы уже есть в `Club\TournamentController`, `AmericanoController`, `MexicanoController`, `TeamTournamentController`, `KingOfCourtController`. Нужно:

- Создать аналогичные API-роуты `/api/mobile/admin/tournaments/{id}/...`:
  - `POST /start` — start tournament
  - `POST /finish` — finish
  - `PUT /` — update fields
  - `POST /participants/{user_id}/approve` — модерация
  - `POST /participants/{user_id}/reject`
  - `DELETE /participants/{user_id}` — удаление
  - `POST /matches/{match_id}/score` — ввод счёта (по типу)
  - `POST /next-round` — генерация раунда (Mexicano/KOC)
  - `POST /generate-playoff` — плей-офф

Каждый — thin wrapper над существующим сервисом.

#### Мобила

- `AdminTournamentDetailScreen` с табами:
  - **Инфо** — поля для редактирования + кнопки «Запустить», «Завершить», «Удалить»
  - **Участники** — список с плашками статуса (registered / pending / cancelled), кнопки одобрить/отклонить/удалить
  - **Раунды/Матчи** — переиспользуем существующие live-экраны (live screens уже умеют отображать), добавляем редактируемые поля счёта для админа
- Подтверждения для опасных действий через `showAppAlert` или `AlertDialog`

#### Что проверить (после этого этапа главная сила админа)

- ✅ Создать турнир в Web (любой тип)
- ✅ Через мобилу: одобрить заявки → запустить → ввести счёт всех матчей → сгенерить раунды/плей-офф → завершить → проверить что ELO применился
- ✅ Каждый из 4 типов отдельно проверить (americano / mexicano / team / king_of_court)
- ✅ В Web-админке всё то же самое отображается корректно после действий с мобилы

### ЭТАП 4 — Создание турнира

**Цель:** админ создаёт новый турнир целиком из мобилы.

#### Бэкенд

- `POST /api/mobile/admin/club/{clubId}/tournaments`
- Body аналогично web `/tournaments` POST
- Валидация: `type` ∈ {americano, mexicano, team, king_of_court}, остальные поля по типу
- Возвращает `id` нового турнира

#### Мобила

- Кнопка «+» в `AdminClubScreen`
- Wizard из 4-х экранов:
  1. **Тип турнира** (визуальный выбор из 4 карточек с иконками и описанием)
  2. **Основное** (название, дата/время, клуб (auto), уровни min/max, max_participants, цена)
  3. **Специфика типа** (для Americano — кол-во групп/раундов; для Mexicano — раунды; для Team — групп/выходит; для KOC — авто)
  4. **Корты + плей-офф** (галочки has_playoff, has_lower_bracket, has_bronze_match, корты с названиями)
- Финальная кнопка «Создать» → API call → редирект на `AdminTournamentDetailScreen`

#### Что проверить

- ✅ Создание каждого из 4 типов с разными параметрами
- ✅ Турнир появляется в Web-админке корректно (поля совпадают)
- ✅ Турнир появляется в публичном списке мобилы (если статус `open`)
- ✅ Можно сразу запустить и доиграть

## Решённые вопросы (зафиксировано 2026-04-28)

1. **Где админский вход в мобиле?** → Не таб в нижнем меню. **Блок на главном экране** для `club_admin`-а — большие кнопки-CTA (стиль как существующий «Создать турнир»). Например: «Мои турниры (как админ)», «Создать турнир». При тапе на турнир из этого блока — открывается админский экран турнира.
2. **Wizard или форма?** → **Одна форма** со свёрнутыми блоками (accordion). Заголовки секций раскрываются по тапу. Внизу — одна кнопка «Создать».
3. **Редактируемые счета и админ-действия** → **Отдельные админ-экраны.** Существующие live-screens НЕ трогаем — это чистый read-only UI для зрителя/участника. Админский функционал в параллельных `Admin*Screen`.
