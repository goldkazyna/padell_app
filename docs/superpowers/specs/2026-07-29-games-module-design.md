# Модуль «Игры» (games) — проектная спецификация

**Дата:** 2026-07-29
**Статус:** дизайн утверждён пользователем (детали — на усмотрение исполнителя, всё зафиксировано для будущей доработки)
**Репозитории:** backend Laravel `C:\projects\padel`, frontend Flutter `C:\projects\padel_app`

---

## 0. Резюме и цель

Игрок сам создаёт игру (тренировку/матч), собирает состав из 4 человек, а после старта проводит игру в одном из трёх форматов и фиксирует счёт. Рейтинговые игры идут в расчёт ELO.

Пишем **новый домен `games`** рядом со старым `challenge` (старый НЕ трогаем, удалим после запуска нового). Переиспользуем существующую инфраструктуру.

### Терминология (важно!)
- Третий формат — **«Американо»** (ротация «каждый с каждым», личные очки). В исходном ТЗ его назвали «Король корта» — это неточность. У нас King of Court — отдельный тип турнира с другой механикой; в играх используем именно **Американо** (та же логика, что в турнирах Американо).

## 1. ⚠️ Безопасность рейтинга (жёсткое требование)

**Существующие рейтинги игроков и алгоритм подсчёта не ломать.**

- `App\Traits\RatingCalculator` и `App\Support\AmericanoRanking` переиспользуются **как есть, без изменений** (они общие с турнирами — правка сломает турниры).
- Новый домен пишет в `users.rating` и `rating_history` тем же способом, что старый challenge (`reason='game'`).
- Игры — это новые матчи, они лишь **добавляют** изменения рейтинга, как любой матч. Существующие записи не пересчитываются.
- Рейтинг применяется **один раз** при финализации счёта (идемпотентный guard: если `rating_change` у игроков уже проставлен — повторно не применять).
- Рейтинг начисляется только: `type=rated` И 4 зарегистрированных пользователя (не гости) И минимум один сыгранный раунд.
- `friendly` рейтинг НЕ трогает никогда. `cancelled`/`disputed` — рейтинг не применяется.

## 3. Границы: MVP vs Фаза 2

### MVP (первая отгрузка)
- Создание игры: клуб(обяз)/корт(опц), старт+конец, тип rated/friendly, **приватность public/private**, формат+параметры, диапазон рейтинга, цена, описание
- Роли: организатор / участник / приглашённый / кандидат
- Заявки из ленты и по ссылке → одобрение организатором; персональное приглашение (слот сразу); **ссылка-приглашение** (отзыв/перевыпуск, срок, лимит)
- Исключения по рейтингу: приглашение сильнее фильтра; организатор может быть вне своего диапазона (инфо, не блок); тумблер «показывать игры вне моего уровня»
- **Три формата счёта** (sets / points / americano) + отменяемость до `score_locked` + базовый action-log с «отменить последнее действие»
- Передача прав организатора (+ выход организатора после передачи)
- Утверждение счёта: сводка → lock; для rated — подтверждение участников (≥2 или авто через 24ч); `disputed` только помечаем
- Лента игр (только public) с фильтрами + «Мои игры» (табы)
- Инбокс «Приглашения» — только игры, но таблица/API **полиморфные**
- Пуши по событиям + напоминания 24ч/2ч

### Фаза 2 (не сейчас, но заложено)
- Чаты (лобби + внутренний)
- Веб-CRM для разбора споров (админ разблокирует счёт). В MVP спор = флаг `disputed`, счёт остаётся залоченным до ручного вмешательства
- Инбокс: реальные турниры/тренировки (сейчас заглушки-ссылки)
- Гостевой игрок без аккаунта; Американо на 5–8 игроков (отдыхающие, второй корт)
- Продвинутый «откат до состояния» из истории изменений; репутация/счётчик отмен
- Общий чат клуба

## 5. Жизненный цикл игры (status)

```
open ──(4 accepted)──> full ──(start)──> in_progress ──(утвердить счёт)──> finished
  │                      │                    │
  └──────────────────────┴────────────────────┴──> cancelled (организатор)
                                             (rated, возражение) └──> disputed
```

- `open` — ждёт набора состава
- `full` — 4 accepted, новые заявки не принимаются (поданные остаются в листе ожидания)
- `in_progress` — идёт игра, ввод счёта; «Отменить старт» доступен до lock
- `finished` — счёт утверждён, `score_locked=true`
- `cancelled` — отменена организатором
- `disputed` — рейтинговая, возражение участника (Фаза 2 — разбор админом; в MVP просто флаг)

## 6. Роли и доступ

### Роли (вычисляются из данных, не хранятся отдельно)
| Роль | Как определяется | Права |
|---|---|---|
| Организатор | `user_id == games.creator_id` | всё: параметры, приглашения, приём/отклонение заявок, удаление игроков, формат, расстановка пар, ввод/отмена счёта, отмена игры, передача прав |
| Участник | `game_players.status=accepted` и не организатор | просмотр, выход до `in_progress`, подтверждение счёта, приём роли при передаче |
| Приглашённый | `status=invited` | принять/отклонить; слот не занимает |
| Кандидат | `status=candidate` | отзыв заявки |
| Сторонний | не в игре | видит только public в ленте, может подать заявку |

### Приватность
- `public` — видна в ленте/поиске; вход: заявка → одобрение / приглашение / ссылка
- `private` — не видна нигде; вход: приглашение / ссылка → заявка → одобрение
- Организатор переключает public ↔ private в любой момент до lock; при переключении в private игра уходит из ленты, поданные заявки сохраняются

### Ссылка-приглашение (для обоих уровней)
- Генерится автоматически при создании (`share_token`)
- Кнопка «Поделиться»; отзыв + перевыпуск (старая перестаёт работать: `share_revoked_at`, новый токен)
- Опц. срок (`share_expires_at`, по умолчанию = `starts_at`) и лимит (`share_max_uses`)
- Переход неавторизованным → регистрация → карточка игры → заявка

### Вход в состав всегда одобряет организатор. Исключение — персонально приглашённый (сразу accepted после «Принять»).

### Исключения по рейтингу (§4 ТЗ)
- Персональное приглашение сильнее фильтра: можно пригласить вне диапазона; в карточке пометка «вне диапазона — по приглашению» (`out_of_range=true`)
- Организатор может быть вне своего диапазона — инфо-сообщение, НЕ блок
- Диапазон = фильтр только для «самотёка» (лента/ссылка). Не подходящим по рейтингу игра по умолчанию скрыта (тумблер «показывать вне уровня»). Если открыл — предупреждение, заявка уходит с пометкой, организатор решает

## 7. Форматы и движок счёта

Формат выбирается при создании, меняется до `score_locked` (со сбросом введённого счёта, с подтверждением).

### 7.1 `sets` — классика по сетам
- Организатор добавляет сеты по одному
- Пары A/B задаются на уровне сета (по умолчанию — состав предыдущего), пресеты разбивки при 4 игроках: «1+2 / 3+4», «1+3 / 2+4», «1+4 / 2+3»
- Счёт = геймы + опц тай-брейк
- `format_meta`: `{ tiebreak: bool }`

### 7.2 `points` — до N очков
- `format_meta`: `{ points_mode: 'first_to'|'total', points_target: int, points_cap: int|null }`
  - `first_to` — до N очков, побеждает первый
  - `total` — фикс число розыгрышей/время, побеждает набравший больше
  - `points_cap` — «с разницей в 2, но не более чем до M»
- Пресеты target: 16/21/24/32 + свободный ввод
- Пары один раз на партию, можно менять и добавлять партии («+ Ещё партия»)
- Ввод: два числа (очки A / очки B)

### 7.3 `americano` — ротация (в ТЗ ошибочно «Король корта»)
- `format_meta`: `{ sub: 'by_sets'|'by_tiebreak'|'by_points', target: int }`
  - `by_sets` — раунд = короткий сет (до 4/6 геймов)
  - `by_tiebreak` — раунд = тай-брейк (до 7/11/21)
  - `by_points` — раунд = розыгрыш до N очков
- Авторасписание на 4 игрока (3 раунда, каждый с каждым):

| Раунд | Пара A | Пара B |
|---|---|---|
| 1 | 1+2 | 3+4 |
| 2 | 1+3 | 2+4 |
| 3 | 1+4 | 2+3 |

- Генерится при старте; организатор может перегенерировать / перетасовать / вручную переставить — до lock
- Очки начисляются **лично каждому игроку** = сколько набрала его пара в раунде
- Итоговая таблица (через `AmericanoRanking`): место, игрок, сумма очков, разница, победы в раундах; тай-брейк: разница → победы → личная встреча
- Победитель — макс личных очков

Американо на 5–8 игроков (отдыхающие, 2-й корт) — **Фаза 2**.

## 8. Отменяемость и утверждение счёта

### Базовое правило
Пока `score_locked=false` — организатор может отменить/переделать что угодно (параметры, приватность, формат, пары, расписание, счёт, замена участника, отмена старта, отмена игры). Матрица прав до старта / после старта до lock / после lock — см. §8.1 ТЗ (после lock — только через админа, Фаза 2).

### Механика
- «Отменить последнее действие» — откат последней записи `game_action_logs`
- Модалка-подтверждение для разрушающих действий («сбросит счёт раундов 1–2»)
- Snackbar «Вернуть» после мутаций (быстрый откат)
- Экран «История изменений» (в MVP — просмотр лога; откат-до-состояния — Фаза 2)
- Автосейв черновика счёта

### Утверждение
1. «Завершить игру» → сводка (формат, раунды, пары, счёт, таблица americano)
2. Подтверждение «после утверждения изменить нельзя» → `finished`, `score_locked=true`
3. rated: участники получают «Подтвердить счёт»; рейтинг применяется после подтверждения ≥2 участников ИЛИ авто через 24ч без возражений
4. Возражение → `disputed` (Фаза 2 — разбор админом; в MVP только флаг)
5. friendly: счёт фиксируется сразу, рейтинг не трогает

### Валидация счёта
- Каждый игрок ровно в одной команде раунда
- Счёт неотрицательный, в разумных границах (sets 0–9 геймов + тай-брейк; points ≤ target + допуск 2)
- Ничьей в завершённом раунде быть не может
- americano: все раунды должны быть заполнены (иначе предупреждение)

## 9. Передача прав организатора

1. Организатор до `finished` жмёт «Передать организацию» → выбирает `accepted`-участника
2. `game_transfers(pending)` + пуш + карточка выбранному: «Принять?»
3. До принятия права у прежнего; отказ → можно предложить другому
4. Принятие: `games.creator_id = to_user`; прежний становится участником; системная запись
5. **Прежний организатор после передачи может выйти** — единственный способ организатору покинуть игру. Освобождённый слот → `open`
6. Организатор выходит, а участников кроме него нет → игра `cancelled`
7. Передавать можно неограниченно; история в `game_transfers`
8. Только `accepted`-участнику (не invited/candidate)

## 10. Инбокс «Приглашения»

- Отдельный раздел, вход с главного экрана, иконка с бейджем = кол-во `invitations.status=pending`
- Табы: Все / Игры / Турниры / Тренировки (в MVP реально только Игры; турниры/тренировки — заглушки-ссылки на будущие модули)
- Карточка игры: кто приглашает (фото/имя/рейтинг), клуб, корт, дата/время, формат, тип, состав принявших, цена, диапазон + пометка «вы вне диапазона, приглашены лично»
- Действия: Принять / Отклонить / Открыть / Написать организатору (чат — Фаза 2)
- После ответа → подраздел «Обработанные»; просроченные — серым
- Свайп: влево отклонить, вправо принять (+ snackbar «Вернуть»)
- Отклонённое можно прислать повторно (не более 2 раз)
- Принятие = занятие слота; если уже 4 — «Мест больше нет», приглашение просрочено

## 15. Бизнес-правила (сводка)

1. Два уровня приватности; переключаются организатором до lock
2. Слот занят только при `accepted`; приглашения/заявки слот не резервируют
3. Максимум 4 `accepted`; пятый — нельзя
4. Диапазон рейтинга — фильтр для «самотёка», не жёсткое ограничение; приглашение перекрывает; организатор может быть вне
5. Игрок в двух играх с пересекающимся временем — мягкое предупреждение
6. Организатор не может просто выйти — либо отменяет, либо передаёт права, потом выходит
7. Передать права — только `accepted`-участнику
8. Выход участника — до `in_progress`; после — только удаление организатором
9. Пока `score_locked=false` — любое действие обратимо
10. rated засчитывается только при 4 зарегистрированных и ≥1 сыгранном раунде
11. Для americano рейтинг — по личным очкам игрока
12. Отмена позднее 2ч до старта — фиксируется (репутация, Фаза 2)
13. Ссылку можно отозвать/перевыпустить
