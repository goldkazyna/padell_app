# Just Padel It в приложении — под-проект A: создание (дизайн)

**Дата:** 2026-07-05
**Статус:** утверждён, к плану реализации
**Область:** приложение (Flutter `padel_app`) + мобильный API (Laravel `padel`)

## Контекст

Формат `just_padel_it` полностью реализован и проведение работает на вебе
(движок «Король корта» + бонусы за корт + своя таблица; таблицы, модели и
`JustPadelItService` уже написаны и запушены). Задача — дать администратору
создавать и проводить такой турнир прямо из приложения. Работа разбита на два
под-проекта:

- **A (этот spec):** создание JPI-турнира из мобильной формы.
- **B (отдельный spec, следом):** проведение в app — админское (пары, ввод
  счёта, следующий раунд, итоговая таблица) + live-экран просмотра для
  игроков/зрителей, по паттерну Короля корта.

Этот spec покрывает только под-проект A.

## Решения (из брейншторма)

- Полный цикл (создание + проведение) в приложении — но релизим инкрементами:
  сначала A (создание), затем B (проведение + live).
- В под-проекте B live-экран просмотра для игроков включён (не только админ).
- Ручного посева в мобильной форме нет — старт авто-сеет по рейтингу (это уже
  поддержано `JustPadelItService::startTournament(null)`); B к этому вернётся.
- «Тип подсчёта» в форме показываем как на вебе: «По очкам» активно, «По сетам»
  неактивно; в v1 значение не отправляется (бэкенд-дефолт — по очкам).

## Область A

Мобильная форма создания турнира (`admin_create_tournament_screen.dart`)
получает новый тип `just_padel_it`. Мобильный бэкенд создания
(`MobileAdminTournamentController`) принимает этот тип и флаг `is_paired`.
Результат A: администратор создаёт JPI-турнир с телефона (статус `open`). До
готовности B проведение выполняется на вебе.

## Изменения — бэкенд (`C:\projects\padel`)

Файл: `app/Http/Controllers/Api/MobileAdminTournamentController.php`

1. **Валидация типа.** В `tournamentValidationRules()` правило типа сейчас:
   `'type' => 'required|in:king_of_court,americano,americano_flex,bali_koc,team,round_robin'`.
   Добавить `just_padel_it` в список допустимых значений.

2. **Флаг `is_paired`.** Валидация `is_paired` — `nullable|boolean` (не завязана
   на тип). Но в блоке маппинга по типу `is_paired` принудительно ставится
   `true` только для `americano_flex` и `king_of_court`, иначе `false`:

   ```php
   if ($type === 'americano_flex' && $request->boolean('is_paired')) {
       $validated['is_paired'] = true;
   } elseif ($type === 'king_of_court' && $request->boolean('is_paired')) {
       $validated['is_paired'] = true;
   } else {
       $validated['is_paired'] = false;
   }
   ```

   Добавить ветку для JPI, чтобы фиксированные пары сохранялись:

   ```php
   } elseif ($type === 'just_padel_it' && $request->boolean('is_paired')) {
       $validated['is_paired'] = true;
   } else {
   ```

Новых полей БД нет: `finalizeTournamentCreate()` уже делает
`Tournament::create($validated)`; enum `tournaments.type` уже содержит
`just_padel_it` (миграция веб-части).

> Деплой: изменения бэкенда коммитятся и пушатся сразу (правило проекта).
> Отдельная миграция не нужна.

## Изменения — приложение (`C:\projects\padel_app`)

Файл: `lib/screens/admin/admin_create_tournament_screen.dart`

1. **Карточка типа.** В горизонтальный список карточек типов добавить карточку:
   - `value: 'just_padel_it'`
   - `title: 'Just Padel It'`
   - `subtitle: 'Движение по кортам + бонусы'`
   - `icon: Icons.local_fire_department_outlined`

2. **Переключатель «Пары».** В условие показа `_pairedToggle()`
   (сейчас `if (_type == 'americano_flex' || _type == 'king_of_court')`)
   добавить `|| _type == 'just_padel_it'`. Реюз существующего состояния
   `_flexIsPaired` и виджета `_pairedToggle()` («Фиксированные / Случайные»).

3. **`is_paired` в теле запроса.** Рядом с существующей веткой
   `if (_type == 'king_of_court' && _flexIsPaired) { body['is_paired'] = true; }`
   добавить симметричную ветку для `just_padel_it`:
   `if (_type == 'just_padel_it' && _flexIsPaired) { body['is_paired'] = true; }`.
   Отдельную проверку чётности числа игроков в форме не добавляем (её нет и у
   KoC; ограничения по числу игроков/пар проверит сервис при старте в B).

4. **Скрыть «Кол-во раундов» для JPI.** Поле `_roundsCount` не относится к
   JPI (раунды генерируются вручную). Повторить для `just_padel_it` то же
   условие показа/скрытия, что уже применяется к `king_of_court` (у KoC поле
   числа раундов не показывается). Реализация: там, где поле раундов условно
   не рендерится для KoC, добавить `just_padel_it` в то же условие.

5. **Контрол «Тип подсчёта».** Показать для `just_padel_it` небольшой блок с
   двумя опциями:
   - «По очкам» — выбрано, активно.
   - «По сетам» — неактивно (задизейблено), подпись/намёк «скоро».
   Значение в теле запроса **не отправляется** (v1 — всегда по очкам). Контрол
   чисто визуальный, повторяет идентичность веб-формы. Показывать только когда
   `_type == 'just_padel_it'`. Строки — через существующий подход экрана
   (админ-экраны допускают хардкод RU по правилу проекта).

Тип уже уходит на бэкенд через существующее `'type': _type` в теле — отдельная
строка не нужна.

## Тестирование A

- **Бэкенд (PHPUnit, `C:\projects\padel`):** тест на создание турнира типа
  `just_padel_it` через мобильный эндпоинт создания — solo (без `is_paired`) и
  paired (`is_paired: true`): ответ успешный, в БД строка с `type` =
  `just_padel_it` и корректным `is_paired`. Отрицательный кейс валидации не
  обязателен (правило `in:` покрывается положительным).
- **App:** ручная проверка — карточка «Just Padel It» выбирается; при выборе
  появляется переключатель «Пары» и контрол «Тип подсчёта» (с задизейбленной
  «По сетам»); поле «Кол-во раундов» скрыто; создание solo и paired проходит,
  турнир появляется в списке. (Автотестов виджета в проекте нет — как у прочих
  типов.)

> Правило проекта: приложение (`padel_app`) не пушим — пользователь собирает
> локально `flutter run`. Бэкенд (`padel`) пушим сразу.

## Вне области A (уйдёт в под-проект B)

- Проведение в app: ветки `just_padel_it` в `MobileAdminTournamentDetailController`
  (`show` / `matches` / standings / `saveScore` / `nextRound`) + пары
  (`jpiPairs`/`saveJpiPairs`) + маршруты, вызывающие `JustPadelItService`.
- App-экраны проведения: создание пар для paired, ввод счёта, следующий раунд,
  итоговая таблица (очки + бонусы + победы).
- Live-экран просмотра для игроков/зрителей (раунды + таблица), как у KoC.
- Реальный посев/выбор порядка на мобилке (в A — авто по рейтингу на старте B).
- «По сетам» как рабочий режим.
